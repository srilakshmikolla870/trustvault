# TrustVault Threats

Status key: **planned** means the control is not implemented or verified.

| ID | Threat and attack path | Impact | Planned control | Test / verification | Status and residual risk |
|---|---|---|---|---|---|
| TV-01 | A user changes a document ID in a listing or download request (IDOR). | Confidential document disclosure or modification. | Listing is scoped to ownership/current grant; download and metadata edit check current owner/grant; denied and missing resources share 404. | `DocumentServiceTest.downloadDeniesDifferentOwnerBeforeReadingPrivateBytes`; `viewerWithoutCurrentGrantCannotDownload`. | Enforcement and service tests are implemented; local Maven test run and HTTP checks pending. Search/detail routes do not exist yet. |
| TV-02 | A revoked viewer reuses a session or previously issued URL. | Revoked access continues. | No reusable URLs are issued; current grant is queried for each list/download/edit request. | `viewerWithCurrentReadGrantCanDownload`; next add a revoke-then-request PostgreSQL test using the same session. | Per-request check is implemented; unit tests do not prove transaction/revocation behavior against PostgreSQL yet. |
| TV-03 | A search endpoint leaks names, counts, snippets, or pagination. | Document existence and metadata disclosed. | Scope query to authorized documents before filtering and pagination. | Search/count leakage tests across users. | Planned; search does not exist yet. |
| TV-04 | A crafted filename or MIME type bypasses upload checks. | Unsafe content stored or executed; resource exhaustion. | PDF-only allow-list; 10 MiB multipart cap; extension, declared MIME, and `%PDF-` signature checks; generated UUID storage key; only attachment downloads with `nosniff`. | `DocumentServiceTest.uploadRejectsPdfExtensionWithNonPdfSignature`; more malformed/oversize/path tests required. | Implemented; the user's full Maven run passed 14 tests. Signature check validates the header only and does not parse full PDF structure. |
| TV-05 | Storage is exposed publicly or file URLs bypass the API. | Unauthenticated access or revocation bypass. | Local storage outside frontend root; generated opaque key; bytes served only after an API ownership check; no public URL. | Inspect deployment policy and local filesystem permissions; request file without session. | Private local storage path is implemented; actual OS/deployment permissions and persistent production storage are unverified. |
| TV-06 | Audit events are omitted or rewritten. | Inability to establish who accessed or changed a resource. | Authentication/admin and document upload/download code writes safe audit rows without bytes or storage keys; DB-level insert-only controls still needed. | Existing auth/admin service tests; document audit assertions and database privilege tests. | Document event writer implemented; the user's full Maven run passed 14 tests, though these do not assert every audit path. Denied servlet-level multipart rejection is not covered; tamper resistance is not implemented. |
| TV-07 | Client forges role, owner, permission, or storage key. | Privilege escalation or cross-user access. | Actor comes from the authenticated server principal; grant target/permission are validated; storage key and owner ID are never accepted from document API input. | Document service grant/download tests; HTTP tests with forged role/owner fields still needed. | Implemented in source; backend suite and direct API attack checks pending. |
| TV-08 | Stored metadata contains script content rendered by the UI. | Stored XSS against users or administrators. | Escape output and use safe attachment handling. | Render script-like title and filename fixtures. | Document metadata views and upload filenames do not exist yet; React escapes current account display fields by default. |
| TV-09 | Secrets are committed or exposed through logs/errors. | Account, database, or storage compromise. | Environment configuration, sanitized errors, secret-free repository. | Scan repository/config and inspect error/log behavior. | Initial `.env.example` only; not yet scanned or deployed. |
| TV-10 | A disabled user reuses an existing authenticated session. | Account revocation does not take effect. | Reload active status and role from the database on each authenticated request; invalidate inactive sessions. | Disable an account during an active session and retry an authenticated request. | Implemented in source, runtime verification pending. |
| TV-11 | Login endpoint is used to enumerate users or brute-force credentials. | Account discovery or account compromise. | Generic login response and BCrypt; rate limiting remains required. | Compare unknown-user/wrong-password responses and exercise configured rate limit. | Generic response implemented; rate limiting and timing review pending. |
| TV-12 | A cross-site request forges login/logout or later state-changing actions. | Session confusion or unwanted actions. | Session-bound CSRF token required on unsafe methods; SameSite=Strict session cookie. | Verify missing/invalid token is rejected for login/logout and later mutations. | Implemented in configuration, runtime verification pending. |
| TV-13 | Stored password hashes are retained in serialized authenticated sessions. | A session-store disclosure also exposes password hashes. | Principal implements credential erasure; per-request refreshed principals omit password hashes. | Inspect authenticated principal after login and verify password hash is absent; test credential erasure. | Implemented in source, runtime verification pending. |
| TV-14 | A non-admin calls user-management APIs directly or forges the requested role. | Unauthorized account creation, privilege escalation, or user enumeration. | Require server-side `ROLE_ADMINISTRATOR` for `/api/admin/**`; allow account creation only for OWNER/VIEWER; return password-free summaries; audit denied admin access. | `UserAdminServiceTest` rejects administrator role; manually test direct API as owner/viewer and anonymous user. | Enforcement and audit are implemented in source; service tests added but not yet run; HTTP denial and audit behavior remain unverified. |
| TV-15 | An administrator disables their own account or disables a privileged administrator by mistake. | Administrative lockout. | Disallow self-status changes and status changes to administrator accounts. | `UserAdminServiceTest.preventsAdministratorFromDeactivatingTheirOwnAccount`; manually verify administrator target is rejected. | Implemented in source; tests not yet run; recovery requires an authorized database operator if every admin becomes inactive through direct DB changes. |
| TV-16 | A new user's password or hash is exposed through the admin API or UI. | Account compromise. | BCrypt before persistence; response DTO contains only safe account fields; never list password/hash. | `UserAdminServiceTest.createsNormalizedViewerWithEncodedPasswordAndAuditEvent`; inspect JSON response and React rendering. | Implemented in source; tests and HTTP response inspection pending. |

No control in this file should be treated as implemented until code and verification evidence are added.
