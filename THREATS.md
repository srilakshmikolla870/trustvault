# TrustVault Threats

Status key: **planned** means the control is not implemented or verified.

| ID | Threat and attack path | Impact | Planned control | Test / verification | Status and residual risk |
|---|---|---|---|---|---|
| TV-01 | A user changes a document ID in a listing or download request (IDOR). | Confidential document disclosure or modification. | Listing is scoped to ownership/current grant; download and metadata edit check current owner/grant; denied and missing resources share 404. | `DocumentServiceTest.viewerListingUsesVisibilityScopedRepositoryQuery`; `downloadDeniesDifferentOwnerBeforeReadingPrivateBytes`; `viewerWithoutCurrentGrantCannotDownload`. | Source inspection confirms the repository query scopes visible documents by owner or current grant. The service unit test verifies it uses that query, but does not execute the JPQL against a database. Backend unit suite passed 26 tests on 2026-10-22; direct HTTP authorization checks remain pending. Search filters were added after the visibility-scoped list query; soft-deleted records are excluded from active list and download paths. Detail routes do not exist yet. |
| TV-02 | A revoked viewer reuses a session or previously issued URL. | Revoked access continues. | No reusable URLs are issued; current grant is queried for each list/download/edit request. | `viewerWithCurrentReadGrantCanDownload`; next add a revoke-then-request PostgreSQL test using the same session. | Per-request check is implemented; unit tests do not prove transaction/revocation behavior against PostgreSQL yet. |
| TV-03 | A search endpoint leaks names, counts, snippets, or pagination. | Document existence and metadata disclosed. | Scope query to authorized documents before filtering and pagination. | DocumentServiceTest.documentSearchFiltersOnlyDocumentsReturnedByVisibilityScopedQuery. | Backend unit suite passed 26 tests on 2026-10-22, including service-level coverage; direct HTTP and database isolation checks remain pending. |
| TV-04 | A crafted filename or MIME type bypasses upload checks. | Unsafe content stored or executed; resource exhaustion. | PDF-only allow-list; 10 MiB multipart cap; extension, declared MIME, and `%PDF-` signature checks; generated UUID storage key; only attachment downloads with `nosniff`. | `DocumentServiceTest.uploadRejectsPdfExtensionWithNonPdfSignature`; more malformed/oversize/path tests required. | Backend unit suite passed 26 tests on 2026-10-22. Signature check validates the header only and does not parse full PDF structure. |
| TV-05 | Storage is exposed publicly or file URLs bypass the API. | Unauthenticated access or revocation bypass. | Local storage outside frontend root; generated opaque key; bytes served only after an API ownership check; no public URL. | Inspect deployment policy and local filesystem permissions; request file without session. | Private local storage path is implemented; actual OS/deployment permissions and persistent production storage are unverified. |
| TV-06 | Audit events are omitted or rewritten. | Inability to establish who accessed or changed a resource. | Server audit writer plus insert-only database protections; runtime DB login must not own or alter protected tables. | V2 triggers; production role script; test inserts and rejected UPDATE/DELETE/TRUNCATE using runtime login. | Disposable PostgreSQL 16 verification passed on 2026-10-22: runtime privileges, audit append, and trigger rejection of audit-row UPDATE even as the table owner were confirmed. The script has not been applied to production. A database superuser remains trusted and could alter or disable triggers. |
| TV-07 | Client forges role, owner, permission, or storage key. | Privilege escalation or cross-user access. | Actor comes from the authenticated server principal; grant target/permission are validated; storage key and owner ID are never accepted from document API input. | `DocumentServiceTest.viewerCannotListGrantsOrGrantAccessToAnotherDocument`; `viewerCannotRevokeAnotherOwnersGrant`; direct HTTP tests with forged role/owner fields still needed. | Backend unit suite passed 26 tests on 2026-10-22. Direct API attack checks remain unverified. |
| TV-17 | A Viewer without a grant tries to edit metadata or manage another owner's permissions. | Unauthorized changes or privilege escalation. | Edit requires ownership or a current EDIT grant; grant listing, creation, and revocation require the document owner role and ownership check. | `DocumentServiceTest.viewerWithoutGrantCannotEditAnotherOwnersMetadata`; `readOnlyViewerCannotEditMetadata`; `viewerCannotListGrantsOrGrantAccessToAnotherDocument`; `viewerCannotRevokeAnotherOwnersGrant`. | Regression tests and no-write assertions are included; the full backend unit suite passed 26 tests on 2026-10-22. HTTP-level checks remain pending. |
| TV-19 | A compromised API process writes an elevated role, activates a disabled account, or changes a document grant directly in PostgreSQL. | Account takeover or unauthorized document access. | Treat the API process as trusted because it must write accounts and grants; use a non-owner runtime DB role, restrict schema/migration authority, audit application operations, and protect audit rows from mutation. | Apply the deployment role script to a disposable database; verify required app workflows, denied SQL audit-row mutations, and document security tests. | The disposable role-hardening check passed on 2026-10-22, confirming the tested role boundary and audit protections. The runtime connection can still write account/grant data needed by normal features, so it cannot distinguish service-approved SQL from direct SQL issued by a compromised API process. This residual risk remains accepted for the MVP; production database application and stronger database-mediated authorization are still outstanding. |
| TV-08 | Stored metadata contains script content rendered by the UI. | Stored XSS against users or administrators. | Escape output and use safe attachment handling. | Render script-like title and filename fixtures. | Document metadata and upload filenames are rendered as React text, which escapes markup by default. Browser XSS verification with script-like metadata is still pending. |
| TV-09 | Secrets are committed or exposed through logs/errors. | Account, database, or storage compromise. | Environment configuration, sanitized errors, secret-free repository. | Scan repository/config and inspect error/log behavior. | Initial `.env.example` only; not yet scanned or deployed. |
| TV-10 | A disabled user reuses an existing authenticated session. | Account revocation does not take effect. | Reload active status and role from the database on each authenticated request; invalidate inactive sessions. | Disable an account during an active session and retry an authenticated request. | Implemented in source, runtime verification pending. |
| TV-11 | Login endpoint is used to enumerate users or brute-force credentials. | Account discovery or account compromise. | Generic login response and BCrypt; rate limiting remains required. | Compare unknown-user/wrong-password responses and exercise configured rate limit. | Generic response implemented; rate limiting and timing review pending. |
| TV-12 | A cross-site request forges login/logout or later state-changing actions. | Session confusion or unwanted actions. | Session-bound CSRF token required on unsafe methods; SameSite=Strict session cookie. | Verify missing/invalid token is rejected for login/logout and later mutations. | Implemented in configuration, runtime verification pending. |
| TV-13 | Stored password hashes are retained in serialized authenticated sessions. | A session-store disclosure also exposes password hashes. | Principal implements credential erasure; per-request refreshed principals omit password hashes. | Inspect authenticated principal after login and verify password hash is absent; test credential erasure. | Implemented in source, runtime verification pending. |
| TV-14 | A non-admin calls user-management APIs directly or forges the requested role. | Unauthorized account creation, privilege escalation, or user enumeration. | Require server-side `ROLE_ADMINISTRATOR` for `/api/admin/**`; allow account creation only for OWNER/VIEWER; return password-free summaries; audit denied admin access. | `UserAdminServiceTest` rejects administrator role; manually test direct API as owner/viewer and anonymous user. | Backend unit suite passed 26 tests on 2026-10-22; HTTP denial and runtime audit behavior remain unverified. |
| TV-15 | An administrator disables their own account or disables a privileged administrator by mistake. | Administrative lockout. | Disallow self-status changes and status changes to administrator accounts. | `UserAdminServiceTest.preventsAdministratorFromDeactivatingTheirOwnAccount`; manually verify administrator target is rejected. | Backend unit suite passed 26 tests on 2026-10-22; HTTP behavior remains unverified. Recovery requires an authorized database operator if every admin becomes inactive through direct DB changes. |
| TV-16 | A new user's password or hash is exposed through the admin API or UI. | Account compromise. | BCrypt before persistence; response DTO contains only safe account fields; never list password/hash. | `UserAdminServiceTest.createsNormalizedViewerWithEncodedPasswordAndAuditEvent`; inspect JSON response and React rendering. | Backend unit suite passed 26 tests on 2026-10-22; HTTP response and browser rendering inspection remain pending. |


| TV-18 | A Viewer retains access after a document is deleted, or an owner accidentally deletes it. | Continued disclosure or loss of recoverability. | Owner-only soft deletion and restore; all list/download paths require ACTIVE status; revoke grants on deletion; keep grants revoked after restore; record both actions. | Manually verify Viewer list/download denial after delete and restore, then re-share and verify access returns. Check both activity entries. | Source implements Owner-only deletion/restoration, revokes grants during deletion, and restoration changes only document status. Runtime verification is pending. Private file bytes remain in local storage; no automated purge or retention policy exists. |

No control in this file should be treated as implemented until code and verification evidence are added.
